# Phase 3 results: AI task allocation

Generated by `python -m hybrid_mapper report` from `data/tasks.csv`: 2432 tasks
(608 transpiled workloads x 4 sampled operating
conditions). Labels come from the ground-truth model in `hybrid_mapper/environment.py` /
`config/environment.yaml`, which simulates effects the Phase 1 rules ignore: exact MPS simulation of weakly
entangled circuits, the Goemans-Williamson Max-Cut heuristic, an HPC node's memory, readout error on sampling,
the shots-for-fidelity trade-off, and random queue waits. **This is a simulation study: the oracle stands in
for real execution feedback until Phase 5.**

Oracle labels: CLASSICAL 1770 (73%), REDESIGN 396 (16%), HYBRID 266 (11%).

Regret = extra cost (J = time + 0.001·energy + 10·QPU-seconds, from `rules.yaml`) over the oracle's choice;
a decision that yields no accepted result also pays a 3600 s penalty.

## Tuned thresholds (augment, random split)

Grid search over `rules.yaml` minimising training regret chose statevector memory
1024 GiB and F_min = {'expect': 0.003, 'sample': 0.03, 'recover': 0.0001}. Tuning helps a little, but no
threshold can express "weakly entangled circuits are classically easy": that needs a feature the rules lack.
Adding that one feature (R3 fed the entanglement bound) is worth far more than tuning; the learned allocators
still beat it because they also learn the remaining interactions listed above.
