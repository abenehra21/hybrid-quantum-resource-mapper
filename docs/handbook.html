Orientation

The 90-second pitch

Say this

Quantum processors are good at a narrow set of hard sub-problems, but they are small, noisy and slow to access. Classical supercomputers handle everything else. Today, deciding which part of an application goes where is done by hand, by experts. We are building a framework that profiles an incoming task (how many qubits, how many two-qubit gates, how precise the answer must be, how noisy the hardware is, what the deadline is) and routes it: run it classically, run it as a hybrid quantum–classical workflow, or send it back for redesign because it cannot work as posed.

Phase 1 is a transparent rule engine: nine ordered checks, every threshold in a config file, every decision explained by the rule that fired. Phase 2 trains models that predict a circuit's cost (gate count, depth, measurement groups) in milliseconds, without building and transpiling it. Phase 3 trains an allocator on execution outcomes. In a simulation study it matches the correct decision on 97% of unseen workloads, against 55% for the fixed rules. When it faces larger problems than it was trained on, its mistakes get expensive, until a small amount of execution feedback fixes them.

Hold one picture in your head: a hospital triage desk. Most patients (computations) go to the general ward (classical HPC) because it is cheap, fast and reliable. A few need the specialist (the QPU), but only for one specific procedure, and the specialist has a long waiting list and a shaky hand. Triage decides who goes where, and most of the time it has to say no to the specialist. The proposal says this outright: the goal is "not to use quantum computing for every problem, but to identify when quantum execution is computationally meaningful."

Foundations

Classical HPC

A CPU core runs one instruction stream very flexibly; a modern CPU has tens of cores. A GPU has thousands of simpler cores that apply the same operation to different data at once, which is what matrix arithmetic, simulation and neural networks need. A node is one server: CPUs, GPUs and RAM. A cluster is thousands of nodes joined by a fast interconnect. That, plus the software that shares it, is high-performance computing.

Two programming styles matter. Shared memory (OpenMP, CUDA) runs many threads inside one node. Distributed memory (MPI) runs separate processes that exchange messages across nodes. Users don't run on the machine directly. They submit job scripts to a workload manager, usually Slurm, which queues them and allocates nodes. Slurm's "generic resource" (GRES) mechanism started with GPUs; IBM and partners extended it so a QPU can be requested the same way (see QCSC).

Bandwidth, not flops, limits quantum simulation

A statevector simulator multiplies a vector of 2ⁿ complex amplitudes by a gate for every gate in the circuit. Each multiply touches the whole vector but does little arithmetic per byte, so the speed limit is memory bandwidth (hundreds of GB/s per node), not compute. That is why the Phase 3 ground-truth model estimates statevector time as gates × 2ⁿ × 32 bytes ÷ bandwidth.

The exponential wall

Leading supercomputers are exascale: 10¹⁸ floating-point operations per second. That is still not enough for problems whose cost doubles with every extra particle or variable. Adding GPUs scales linearly; the problem scales exponentially. That gap is the opening for quantum computing, and also the reason it has to be used selectively.

Qubits, circuits, shots

A bit is 0 or 1. A qubit has a state α|0⟩ + β|1⟩ with complex amplitudes, |α|² + |β|² = 1. Measuring gives 0 with probability |α|² and 1 with probability |β|², and destroys the superposition. With n qubits the state has 2ⁿ amplitudes, one per bitstring: 50 qubits means about 10¹⁵ numbers. That one fact explains why quantum computers might do things classical ones cannot, and why simulating them classically gets expensive.

Misconception to avoid

A quantum computer does not "try every answer at once and return the best". A measurement returns one bitstring. Algorithms arrange interference so wrong answers cancel and good ones reinforce, which only works for problems with special structure.

Gates rotate qubits. Single-qubit gates (X, H, RZ(θ), SX) act on one qubit; two-qubit gates (CNOT, CZ, ECR) act on a pair and create entanglement. A circuit is a sequence of gates. Its width is the number of qubits, and its depth is the number of layers when gates that can run in parallel are grouped together. The two-qubit gate count is the single most important cost number on today's hardware: two-qubit gates are roughly ten times noisier than single-qubit ones (on the FakeFez snapshot, median CZ error is 3.9×10⁻³ against 2.3×10⁻⁴ for SX).

Shots, Sampler and Estimator

One run gives one random bitstring, so circuits are repeated. Each repetition is a shot. Qiskit has two primitives. The Sampler returns bitstrings and their frequencies (used by QAOA and SQD). The Estimator returns an expectation value ⟨O⟩ of an observable, such as a molecule's energy (used by VQE and dynamics).

Physical quantities are written as a Hamiltonian, a weighted sum of Pauli strings:

H = Σᵢ cᵢ Pᵢ , Pᵢ ∈ {I, X, Y, Z}^⊗n e.g. H = 0.4·ZZI − 0.2·XIX + …

The number of terms and the size of their coefficients set the measurement cost. To estimate ⟨H⟩ to precision ε by sampling each term, the shot count scales as

N_shots ≈ ( Σᵢ |cᵢ| / ε )²

Terms that commute qubit-wise (on every qubit, the Paulis are equal or one is I) can be measured together; each such set is a measurement group. Fewer groups means fewer distinct circuits to run, which is why the proposal lists measurement groups as a feature and the Task Profile stores them. A Max-Cut Hamiltonian is all ZZ terms, so it is one group. Chemical accuracy is ε = 1.6 mHa (1 kcal/mol), a common chemistry target.

What EPLG means

Layer fidelity (McKay et al., 2023) runs randomised benchmarking on a whole layer of simultaneous two-qubit gates along a long chain of qubits, so it captures crosstalk and idling errors that isolated-pair benchmarks miss. EPLG converts that into an error per gate that does not depend on the chain length. It is the right single number for "how likely is one two-qubit gate in a real circuit to fail", which is exactly what the fidelity formula needs. One caution from the benchmarking literature: EPLG depends on which qubit chain is measured, so treat it as a representative figure, not a per-qubit truth.

Transpilation and routing

You write a circuit in terms of whatever gates you like, on idealised qubits that all talk to each other. Hardware supports a few native gates (on IBM: CZ, RZ, SX, X) and only lets neighbouring qubits interact. The transpiler bridges the two in stages:

  1. Layout: choose which physical qubit each logical qubit sits on. Qiskit first tries VF2Layout, a subgraph-isomorphism search for a placement where every interaction is already between neighbours.
  2. Routing: if no perfect placement exists, insert SWAP gates to move qubit states next to each other. A SWAP costs three CNOTs. Qiskit uses SABRE (Li, Ding and Xie, 2019), a heuristic that looks ahead to pick SWAPs that serve upcoming gates.
  3. Translation and optimisation: rewrite into native gates and cancel redundancies. optimization_level=3 is the most aggressive.

Routing is why the transpiled two-qubit gate count can be several times the logical count, and why it depends on the topology. Our profiler counts two-qubit gates after transpilation, as instructions whose operation.num_qubits == 2:

def transpile_for(circuit, backend, seed=0):
    return transpile(circuit, optimization_level=3, seed_transpiler=seed, **transpile_kwargs(backend))

def two_qubit_count(circuit):
    return sum(1 for inst in circuit.data if inst.operation.num_qubits == 2)
Something we measured

Transpiling is usually under a second, but a 70-qubit circular-entanglement ansatz on Heron took about 28 seconds, while an 80-qubit one took 1 second. A 70-qubit ring has no exact embedding in heavy-hex, so VF2's search runs to its limit before routing takes over. 20 of the 608 transpiles in the Phase 2 dataset took over 10 seconds. It is a concrete argument for predicting resources instead of always transpiling.

Noise, fidelity, mitigation

If each two-qubit gate succeeds with probability (1 − ε), a circuit with N of them runs without a two-qubit error with probability about

F ≈ (1 − ε)^N = exp( N · ln(1 − ε) ) ≈ e^(−εN)

This is the formula Phase 1 uses, with ε = EPLG. It deliberately ignores single-qubit, readout, idling and crosstalk errors, so it is optimistic. It is the standard first-order estimate, and the gap between it and reality is something later phases can learn.

Error mitigation

Today's hardware has no error correction, so results are cleaned up statistically. Zero-noise extrapolation (ZNE) runs the circuit at amplified noise levels and extrapolates back to zero noise. Probabilistic error cancellation (PEC) learns the noise and cancels it on average by sampling corrected circuit variants (Temme, Bravyi and Gambetta, 2017). IBM's 127-qubit "utility" experiment used probabilistic error amplification, a more controlled form of noise amplification for ZNE (Kim et al., 2023). Readout errors get their own fix: twirled readout mitigation turns readout bias into a measurable factor that can be divided out (van den Berg, Minev and Temme, 2022).

All of these work on expectation values, and all of them cost extra shots. The sampling overhead grows roughly like 1/F²: at F = 0.05 that is 400 times more shots. The project uses 1/F² as a rough multiplier and says so in its limitations.

Error correction, for context

Fault tolerance encodes each reliable logical qubit in many physical ones. IBM's roadmap targets a fault-tolerant system by 2029. Until then every algorithm in this project lives with noise, which is why noise tolerance varies so much between algorithms and why the rules use a different threshold for each.

Simulating circuits classically

This section justifies the proposal's line "a small qubit count does not automatically imply QPU use", and Phase 3 adds the converse: a large qubit count does not automatically imply QPU use either.

Statevector: exact, exponential in n

Store all 2ⁿ amplitudes at 16 bytes each (two 64-bit floats). Memory is 16 × 2ⁿ bytes: 30 qubits = 16 GiB (a workstation), 35 qubits = 512 GiB (a large HPC node), and around 45–50 qubits exceeds the memory of the biggest machines. A 45-qubit circuit was simulated on a supercomputer in 2017 using about half a petabyte (Häner and Steiger). Phase 1's rule R2 uses the 16 GiB line; Phase 3's ground truth assumes a 512 GiB node.

Tensor networks: cheap when entanglement is low

A matrix product state (MPS) writes the state as a chain of small tensors, one per qubit. The size of the bond between neighbouring tensors, the bond dimension χ, must be at least 2^(entanglement across that cut, in ebits). Vidal (2003) showed that circuits that create little entanglement can therefore be simulated efficiently, whatever their width. Memory is about n · χ² · 16 bytes and time about gates · χ³.

The Phase 3 ground truth bounds the entanglement without simulating anything. A CZ gate across a cut can at most double the Schmidt rank there, so the entanglement across a cut is at most the number of CZs crossing it, and never more than the number of qubits on the smaller side. For a linear-entanglement ansatz with r layers, each layer puts one CZ across the middle cut, so the bound is r ebits and χ ≤ 2^r: a 100-qubit, 2-layer ansatz needs χ = 4. That task looks enormous to a rule that only counts qubits.

Other classical shortcuts

  • Clifford circuits (only H, S, CNOT and Paulis) are simulable in polynomial time at any size: the Gottesman–Knill theorem (Gottesman, 1998; Aaronson and Gottesman, 2004).
  • Problem-specific algorithms. For Max-Cut, Goemans–Williamson (1995) guarantees a cut within 0.878 of optimal. Low-depth QAOA's worst-case guarantees on 3-regular graphs are lower (next section).
  • GPU simulators (Qiskit Aer, NVIDIA cuQuantum) speed up both statevector and tensor-network methods.
Say this

A QPU is only worth using when the problem is too large or too entangled to simulate classically and still small and shallow enough to run on noisy hardware. That window is narrow today, and the framework's first job is to find it.

VQE: Variational Quantum Eigensolver

A parameterised circuit (the ansatz) prepares a trial state; the QPU estimates its energy ⟨H⟩ with the Estimator; a classical optimiser adjusts the parameters to lower it (Peruzzo et al., 2014). Hardware-efficient ansätze use layers of native rotations and entangling gates (Kandala et al., 2017); our efficient_su2 workloads are of this type. VQE needs accurate expectation values, so it is noise-sensitive, and it can suffer barren plateaus: in large random circuits, gradients vanish exponentially (McClean et al., 2018).

QAOA: Quantum Approximate Optimisation Algorithm

Alternating cost and mixer layers, p rounds (Farhi, Goldstone and Gutmann, 2014). For Max-Cut each graph edge becomes a ZZ interaction, which costs 2 two-qubit gates per edge per layer, so the logical count is exactly 2·p·|E|. The Sampler returns candidate cuts and the classical side keeps the best. Worst-case guarantees on 3-regular graphs: p = 1 gives at least 0.6924 of the optimum (Farhi et al.), p = 2 at least 0.7559, and p = 3 at least 0.7924 assuming a conjecture about worst-case graphs (Wurtz and Love, 2021). All are below Goemans–Williamson's 0.878.

SQD: Sample-based Quantum Diagonalisation

The QPU only samples likely electron configurations. Classical HPC repairs noisy samples ("configuration recovery"), then solves the problem exactly inside that much smaller subspace. In the IBM–RIKEN study (Robledo-Moreno et al., Science Advances, 2025), a Heron processor ran circuits of up to 77 qubits and 10,570 gates for N₂ and the [2Fe-2S] and [4Fe-4S] iron–sulfur clusters, with the Fugaku supercomputer doing the diagonalisation. The authors themselves say this does not establish that the method beats every classical algorithm.

How the presets use it

The fes_sqd and fes_vqe presets are spec-only profiles in the spirit of that experiment: 77 qubits and an assumed 3,500 two-qubit gates (a fraction of the reported 10,570 total gates). No 77-qubit circuit is built. Present them as illustrative, not as the paper's exact numbers.

SPSA: the optimiser in our baselines

Simultaneous Perturbation Stochastic Approximation (Spall, 1992) estimates a gradient from only two function evaluations, by perturbing every parameter at once in a random ±c direction. That makes it popular for noisy, shot-based objectives. Its step size must suit the scale of the objective. Our first version used a fixed step and barely moved the VQE parameters (4-qubit error about 5 Ha), so baselines.py now calibrates the step from a few sampled gradients, as Qiskit's SPSA does. After the fix, the 4-qubit hybrid VQE reaches −7.87 against an exact −8.53. That bug-and-fix story makes a good interview answer about debugging.

Evaluation discipline

  • Held-out data. Score only on data the model never trained on, or you measure memorisation.
  • Group splits. In Phase 3 the same circuit appears under four operating conditions. Splitting by row would put a circuit's twin in both train and test (leakage). We split by workload with GroupShuffleSplit.
  • Extrapolation split. Train on ≤ 40 qubits, test on 50–120. This is the question that matters: will the model work on problems bigger than anything it has seen?
  • Class imbalance. 68% of Phase 3 tasks are CLASSICAL. We use balanced class weights and report macro-F1.
  • Cost-sensitive learning. Not all mistakes cost the same: sending a doomed job to the QPU wastes far more than wrongly choosing classical. Elkan (2001) shows that weighting training examples by misclassification cost is the principled fix. The gradient-boosting allocator does this.
  • Permutation importance. Shuffle one feature and see how much the score drops (Breiman, 2001). It tells you what the model actually relies on.

Federated learning, briefly (Phase 6)

Each site trains locally and shares only model parameters; a coordinator averages them, weighted by data size. This is FedAvg (McMahan et al., 2017). Two known problems: sites have different data (non-IID), and trees cannot simply be averaged. Our power-law models are linear, so averaging them is exact, which is one reason to keep that family in the toolbox.

Quantum-centric supercomputing

On 12 March 2026 IBM published what it calls the first reference architecture for quantum-centric supercomputing (QCSC): QPUs treated as part of an HPC system. Coverage describes four logical layers: hardware infrastructure, system orchestration, application middleware, and applications. The orchestration layer runs on the Quantum Resource Management Interface (QRMI), which other resource managers like Slurm can call, with a Slurm plugin (SPANK) to expose QPUs as schedulable resources. RIKEN and IBM ran closed-loop exchange between a Heron processor and all of Fugaku for iron–sulfur clusters.

The framing that makes the project click

IBM's architecture provides the plumbing to run a hybrid job once someone has decided the split. The application layer is where that decision lives, and today it is made by hand. Our framework automates the decision, and its output could become the job request that QRMI and Slurm carry out.

  2. SQD is the recover kind, so shots = samples_needed = 3×10⁶.
  3. QPU time = 3×10⁶ ÷ 4,000 = 750 s = 12.5 minutes. Queue 60 + 12.5 = 72.5 min, under the 480-minute deadline.
  4. Same circuit as VQE (fes_vqe, Σ|c| = 50, ε = 10⁻³): shots = (50 / 0.001)² / (5.35×10⁻⁴)² = 2.5×10⁹ / 2.86×10⁻⁷ ≈ 8.7×10¹⁵. At 4,000 shots/s that is about 69,000 years.

Why the fidelity threshold depends on the algorithm

Expect (VQE, dynamics): mitigation overhead is about 1/F², so F = 0.05 already means 400× more shots; below that it is impractical. Sample (QAOA, sampling): you need some fraction of error-free bitstrings; 1% is the starting assumption. Recover (SQD): classical configuration recovery repairs noisy samples, so it tolerates F ≈ 10⁻⁴; the 77-qubit study sat near that. One threshold for all algorithms would be wrong, and the fes_sqd/fes_vqe pair shows why.

How it is coded

The rules are data, not nested ifs: a list of (id, route, predicate, reason-if-fired, reason-if-passed) tuples with lambdas evaluated lazily, in order. The trace is free, the order can be changed for ablations, and the thresholds come from YAML.

Profiler, workloads and baselines

Workloads (workloads.py)

  • Max-Cut: random 3-regular graph (networkx), cost Hamiltonian Σ Z_i Z_j over edges, QAOA circuit from qaoa_ansatz. Cut value = (|E| − ⟨H⟩) / 2, so minimising H maximises the cut.
  • VQE: efficient_su2 ansatz with configurable qubits, layers and entanglement (linear, circular, full), on a synthetic Hamiltonian: seeded random 1–2-body Pauli terms. It is deliberately named synthetic_hamiltonian, and no molecular coefficients are ever typed from memory. The first version used full-weight random Pauli strings, which gave a landscape so rugged that SPSA could not optimise it even without noise; bounded weight is closer to physical models.
  • Random circuits: qiskit.circuit.random.random_circuit with up to 2-qubit operands, a stress test for routing and noise.

Profiler (profiler.py)

Builds the workload, transpiles at optimization_level=3 for the target backend, and fills the circuit fields: logical qubits, transpiled depth, transpiled two-qubit gates, Σ|c|, and qubit-wise measurement groups.

Baselines (baselines.py)

Small instances (≤ 8-qubit VQE, ≤ 12-node Max-Cut) run two ways:

  • classical: exact diagonalisation with numpy for VQE; brute force over 2^(n−1) cuts for Max-Cut (node n−1 fixed by symmetry).

Phase 2 · Resource prediction

Why predict when you can transpile?

  • Speed. Transpiling takes a median 0.7 s per task in our sweep, and up to 30 s. Phase 4 will score many candidate partitions per application; that needs estimates in milliseconds.
  • Before the circuit exists. Predicting from problem-level fields (graph size, ansatz layers, Hamiltonian terms) lets the framework reject hopeless options without building them.
  • Some numbers cannot be computed at all. Runtime, energy and achieved error must be learned from execution logs.

Phase 3 · AI task allocation

What "AI allocation" means here

The proposal: use ML predictions to replace or augment fixed resource-mapping decisions. Two readings, both built:

  • Augment: keep the rules, but feed them Phase 2 predictions instead of exact transpiled fields, or tune their thresholds from data.
  • Replace: learn the decision itself from outcomes, with a classifier.

Judging either needs the right answer for tasks too large to simulate, and that needs execution feedback from real hardware, which is Phase 5. So Phase 3 is a simulation study. A ground-truth model (environment.py) says what would actually happen, using effects from the literature that the Phase 1 rules ignore. The learned allocators see only information available before execution, and meet the hidden effects only through training labels.

Say this before anyone asks

The oracle is a model, not hardware. What Phase 3 shows is that an allocator can recover effects like tensor-network simulability and the shots-for-fidelity trade-off from features known before execution, and that it adapts when fed new outcomes. It does not show that it beats real hardware. The same code retrains unchanged on real outcomes once Phase 5 produces them.

Features the learned allocators get

Problem-level: n, reps, edges, Pauli terms, Σ|c|, analytic count, one-hot family, backend and entanglement. Conditions: precision, ratio target, deadline, nominal queue, budget, samples. Phase 2 predictions: gates, depth, and derived predicted log₁₀ F, log₁₀ shots, (queue + QPU time)/deadline, and one domain feature, log₁₀(budget × F): the number of error-free samples the budget buys. Hidden quantities (entanglement bound, realised queue, readout factor) are never features.

Why the one engineered feature

"Needs about 1,000/F shots against a budget" is a sum of two logarithms. Trees split one feature at a time, so they approximate that diagonal boundary badly, especially outside the training range. Giving the model the physically meaningful combination is standard domain feature engineering, and you should say it was added deliberately.

How a decision is scored

success: regret = J(chosen) − J(oracle) failure: regret = J(wasted attempt) + penalty (3,600)

A failure is any decision that yields no accepted result: a run that misses its target, budget or deadline, or declining a task that was feasible. We also report decision accuracy, macro-F1, success rate, runtime, energy, QPU time, shots, unnecessary QPU use (QPU chosen when a cheaper classical option worked) and communication overhead (QPU jobs per task). Those are the proposal's §10 rows.

Questions your professor is likely to ask

Try answering each out loud before opening it.

Concept

Phase 1 is just if-else statements. Where is the AI?

Deliberately, Phase 1 is the baseline the AI must beat (a column in the proposal's evaluation table) and the generator of labelled data. Every threshold in it is a hypothesis. Phase 2 learns resource predictions and Phase 3 learns the decision itself; on held-out workloads the learned allocator reaches 97% decision accuracy against 55% for the rules. Without the rules we could not show the AI adds anything.

Why would you ever not use the quantum computer?

Because most tasks are cheaper, faster and more accurate classically. Small circuits fit in memory and simulate exactly with no noise and no queue. Weakly entangled circuits simulate as MPS at any width. Some problems, like Max-Cut, have classical algorithms with better guarantees than low-depth QAOA. In our Phase 3 tasks, 68% are best run classically. The framework's value is saying no quickly, with a reason.

Will a QPU ever actually win in your experiments?

In the simulation study, 11% of tasks are best run as hybrid, all of them deep random-circuit sampling where classical simulation runs out. For chemistry and optimisation at these sizes, classical wins. That is a finding, not a failure. We make no quantum-advantage claim; the framework is built to recognise the narrow window when it opens and to adapt as hardware improves.

How does this relate to IBM's QCSC architecture, QRMI and Slurm?

They are complementary. QRMI and the Slurm plugin let a job acquire and use a QPU as a schedulable resource. They do not decide whether a task should use a QPU or how to split it; IBM's architecture leaves decomposition to the application layer. Our framework makes that decision, and its output could become the job request that QRMI and Slurm carry out.

What is new compared with existing quantum schedulers?

Systems like Qonductor schedule jobs that are already destined for a QPU, trading fidelity against completion time. ML work exists on predicting QPU processing time (Xing et al. trained LightGBM on 166,143 IBM jobs). Our focus is upstream: whether each part should be quantum at all, based on problem characteristics, plus resource prediction and learning from feedback.

Physics and hardware

Isn't (1 − ε)^N too crude?

Yes. It ignores single-qubit errors, readout, idling, crosstalk and leakage, so it is optimistic. It is the standard first-order estimate, and EPLG partly absorbs crosstalk because it is measured on whole layers. The Phase 3 ground truth adds readout error, and the gap between estimated and measured fidelity is a natural learning target once real runs exist.

What is EPLG and why use it instead of the two-qubit gate error?

Error per layered gate comes from layer fidelity (McKay et al., 2023): randomised benchmarking on full layers of simultaneous two-qubit gates along a long qubit chain. It includes crosstalk and idling that isolated-pair benchmarks miss, and it is normalised per gate. That is what a real circuit experiences, so it is the right ε for the fidelity formula. It does depend on which chain is measured, so it is a representative figure.

How did you choose 30 qubits and F_min = 0.05?

30 qubits is where statevector memory reaches 16 GiB, a typical workstation; on a 512 GiB node it moves to 35, which is what the Phase 3 ground truth assumes, and threshold tuning picked an even larger memory value. F_min = 0.05 comes from mitigation cost: overhead ≈ 1/F², so 0.05 means about 400× more shots. Both are starting values in rules.yaml, and the SQD example shows why one threshold for all algorithms is wrong.

Why are SQD and VQE so different on the same circuit?

VQE needs an accurate expectation value; noise biases it, and mitigating that bias costs about 1/F² extra shots, which at F ≈ 5×10⁻⁴ is millions of times more. SQD only needs some correct configurations among its samples; classical configuration recovery and diagonalisation in the sampled subspace do the rest, so it tolerates very low fidelity. That is why the rules have an algorithm-aware threshold.

What happens when the problem does not fit the QPU?

The proposal's Function 4 loops back to algorithm design: fewer qubits (smaller active space, fragmentation), lower depth (better ansatz, circuit cutting), or fewer measurements (grouping, lower precision). Phase 1 outputs REDESIGN with the rule's reason, so the user knows which of those to try. Automating that loop is Phase 4.

Why is the Nighthawk transpile target a grid and not the real device?

There is no fake Nighthawk backend in qiskit-ibm-runtime. A 10×12 square lattice matches its published connectivity (square lattice, four neighbours), so it captures routing overhead, which is what matters for gate counts. It does not carry Nighthawk's calibration data, and the config labels it as a topology proxy.

Methodology

Isn't Phase 3 circular? You built an oracle with effects the rules ignore, then showed AI learns them.

It is a simulation study, and we say so. The question it answers is narrower than "does AI beat hardware": can an allocator recover these effects from features available before execution, and does it adapt when given new outcomes? Each effect in the oracle comes from the literature (Vidal on MPS, Goemans–Williamson, published QAOA bounds, measured readout error), not invented to favour the AI. The decisive test is Phase 5, and the pipeline retrains unchanged on real outcomes.

Isn't the rules baseline a strawman? R3 exists but never fires in your Phase 3 numbers.

We checked that directly. The profiler now computes an entanglement bound from the circuit and sets R3 from it, and Phase 3 reports that variant as its own column. It is the fairest rules baseline: 75% accuracy and regret 1,397, against 55% and 2,855 without it. The AI still reaches 97% with regret 285–420. The rules' remaining mistakes are interactions no single threshold captures, such as the Max-Cut heuristic's 0.878 guarantee against a 0.9 target, or a low-fidelity sampling task that a large shot budget rescues.

Is 97% just one lucky train/test split?

No. Repeating the 70/30 workload split with 5 seeds gives 98.3% ± 0.7% accuracy and regret 221 ± 154 for gradient boosting. The decision tree is as accurate (97.2% ± 0.4%) but its regret varies much more (494 ± 751), because a handful of expensive mistakes dominate a mean. That is why we report regret, not only accuracy.

How do you know your Phase 2 test set doesn't leak?

Each circuit is compiled for two backends, and its measurement groups are identical on both. A row-wise random split would put one copy in training and the other in test. We hold out whole circuits on both backends at once; a test checks no circuit appears on both sides. The extrapolation split (train ≤ 40 qubits, test above) cannot leak by construction.

How do you know whether a decision was correct?

For small instances we run every option for real (Phase 1 baselines) and the cheapest option meeting the accuracy target is the oracle label. For large instances we use the ground-truth model. Decisions are scored by accuracy, macro-F1, success rate and regret: the extra cost over the oracle's choice, with failures charged their wasted resources plus a penalty.

Why does classical-only have lower regret than your rules?

Because the costs are asymmetric. A classical attempt that fails is cheap; a QPU job that fails wastes queue time, QPU time and energy. Classical-only fails on a third of tasks, but cheaply. The rules sometimes send doomed jobs to the QPU. This supports the proposal's instinct that classical should be the default, and it is why the gradient-boosting allocator is trained cost-sensitively.

Your AI's regret is worse than classical-only on larger problems. Doesn't that sink it?

It shows the limit of any model trained on one size range: trees predict flat beyond their data, and the HYBRID/REDESIGN boundary was learned from very few large examples. Its accuracy is still 86% against 33% for the rules. The feedback curve is the answer: with 10% of large workloads fed back, regret drops from 5,753 to 2,268, and at 30% to 397, below every baseline. In deployment you pair a learned allocator with a conservative default for out-of-range inputs and retrain as feedback arrives.

How did you avoid data leakage?

Each circuit appears under four operating conditions, so Phase 3 splits by workload (GroupShuffleSplit), never by row. The Phase 2 predictor used inside each Phase 3 evaluation is trained only on that split's training workloads. Hidden quantities (entanglement bound, realised queue, readout factor) are never features.

The classes are imbalanced. How do you handle it?

68% CLASSICAL, 21% REDESIGN, 11% HYBRID. We use balanced class weights, report macro-F1 and per-class confusion matrices, and weight training examples by the cost of getting them wrong (Elkan, 2001).

Why did you add a hand-made feature? Isn't the model supposed to learn?

log₁₀(budget × predicted F) is the number of clean samples the budget buys. The underlying relation is a sum of logs, which axis-aligned tree splits approximate poorly, especially outside the training range. Encoding a physically meaningful quantity is standard practice, it is computed only from pre-execution information, and adding it is reported in the code and the README.

Worst-case bounds for both QAOA and Goemans–Williamson? Real instances do better.

Correct, and we chose worst case on both sides for consistency: both numbers are proven guarantees we can cite (the p = 3 QAOA bound is conditional on a conjecture, which we state). Typical-instance performance of both is better. The assumption is one line in environment.yaml, so the sensitivity is easy to test.

How will you measure energy for QPU jobs?

Classical: node power counters, for example Slurm energy accounting where supported. Quantum: attribute the system's continuous draw by share of QPU time, since the cryostat and electronics run regardless. In the repo both are explicit assumptions (1 kW node, 25 kW QPU system) in config, reported as estimates.

Phase 2 specifics

How do you estimate gate counts before running anything?

Phase 1 does it exactly: build the circuit and transpile it against a fake backend that carries the real layout, at no QPU cost. Phase 2 learns to predict those counts from problem-level features, so the circuit need not be built. On problems larger than any in training, the power-law model is off by 14.5% on average and gives the same decision as the exact count 95.8% of the time.

Why does a power law beat gradient boosting?

Routing overhead grows smoothly with size, so a log-linear form fits it and continues correctly past the training range. Trees are piecewise constant: beyond the largest size they saw, they predict the last leaf's value. Inside the training range the two are comparable; outside it the power law wins. Choosing a model family by its extrapolation behaviour is a real design decision.

Why not just use the analytic formula 2·p·|E|?

It counts gates before routing. Routing adds SWAPs, three CNOTs each, and how many depends on topology: an 80-node Max-Cut needs about 1,500 gates on Nighthawk's grid and 2,450 on Heron's heavy-hex, against 480 logical. That difference flips the decision. The analytic baseline is off by 51% on large problems.

Where is the runtime, energy and error prediction the proposal promised?

Implemented in predict.outcome_models and reported, but trained on only 7 simulated hybrid runs, because each label costs a full run. It beats a mean predictor, but n = 7 only shows the pipeline works. Those labels grow with every baseline run and, properly, with real executions in Phase 5. The resource predictors, trained on 608 transpiler-labelled rows, are the solid part of Phase 2.

Future

How is partitioning automated, since you use templates?

Phase 1 uses one fixed split per algorithm (for SQD: QPU samples, HPC recovers and diagonalises). Phase 4 represents an application as a task graph (a DAG) with data dependencies and transfer costs, then assigns nodes to resources, possibly cutting oversized quantum parts. Phase 2's millisecond predictors make searching over many partitions affordable.

Why federated learning instead of one central model?

HPC centres have different hardware and private workloads they cannot share. Federated learning lets each improve a shared model while keeping raw job data local. Known challenges are non-IID data across sites and model families that can be averaged. Our power-law models are linear, so FedAvg averages them exactly; tree ensembles need other techniques.

What would you do with real QPU access?

Three things: measure real fidelity against the EPLG estimate to learn the residual; replace the ground-truth model's labels with real outcomes for the tasks that are feasible to run; and repeat the feedback-curve experiment with real data, which is the honest test of the research hypothesis.

Limitations, said first

  • Fidelity model. (1 − EPLG)^N ignores single-qubit, readout (in Phase 1), idling and crosstalk errors.
  • Mitigation overhead. 1/F² is a rough multiplier; real PEC/ZNE/PEA costs depend on the method and noise.
  • Thresholds are hypotheses. Every one is in rules.yaml; learning them is the point of Phase 3.
  • One hand-supplied flag. classical_meets_target is not inferred. low_entanglement is inferred from an entanglement bound, an upper bound: a circuit may be easier to simulate than it says.
  • Topology proxy. Nighthawk is a 10×12 grid, not a calibrated device.
  • Synthetic chemistry. VQE Hamiltonians are seeded random bounded-weight Pauli sums, not molecules.
  • Simulated hybrid runs. Runtimes are projected; energy uses assumed power figures; hybrid accuracy reflects a capped SPSA budget.
  • Small execution dataset. Runtime, energy and error models train on 7 runs.
  • Phase 3 is a simulation study. Labels come from a model whose effects come from the literature, compared on worst-case guarantees.

Glossary

Ansatz
A parameterised circuit template whose parameters an optimiser tunes.
Bond dimension χ
Size of the link between neighbouring tensors in an MPS; at least 2^(ebits across that cut).
Chemical accuracy
1.6 mHa ≈ 1 kcal/mol, a common target precision for energies.
Ebit
One unit of entanglement, the amount in one maximally entangled qubit pair.
EPLG
Error per layered gate, from layer-fidelity benchmarking.
Estimator / Sampler
Qiskit primitives returning expectation values / bitstring counts.
FakeFez
A local copy of a real 156-qubit Heron's layout and calibration, used for transpiling and noise.
Heavy-hex
IBM's lattice with at most 3 neighbours per qubit, used by Heron.
Macro-F1
F1 score averaged equally over classes.
MAPE
Mean absolute percentage error.
Measurement group
Pauli terms that commute qubit-wise and can be measured in one circuit.
MPS
Matrix product state, a tensor-network representation efficient for weakly entangled states.
Oracle label
The best decision according to the ground truth, used as the training label and scoring reference.
QCSC
Quantum-centric supercomputing: QPUs integrated as part of HPC systems.
QRMI
Quantum Resource Management Interface, used to acquire and release QPUs from Slurm and other managers.
Regret
Extra cost of a decision over the best decision.
Routing
Inserting SWAPs so interacting qubits are neighbours on the chip.
Shot
One execution and measurement of a circuit.
SPSA
Simultaneous perturbation stochastic approximation, a two-evaluation gradient estimator for noisy objectives.
SQD
Sample-based quantum diagonalisation: QPU samples configurations, HPC diagonalises in that subspace.
Statevector
The full list of 2ⁿ amplitudes describing an n-qubit state.
Transpilation
Rewriting a circuit into a device's native gates and connectivity.
